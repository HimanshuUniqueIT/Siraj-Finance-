Engagement & delivery model

  • AI is used as a developer assistant to compress the timeline; all development, testing and QA are done by Unique IT Solution’s team.
  • Commercials quoted cover the full 10–12 month enterprise scope. A 6–7 month track would deliver the email communication hub only and move SMS / WhatsApp and the wider notification system to Phase 2.
  • Project Manager and Business Analyst effort is not billed; billing is for UI/UX, .NET backend, frontend and AI developers on a critical-path basis, not all full-time.
  • 90-day warranty after production go-live, then AMC (T&M / resource / bug-based).
  • Change requests follow BRD → proposal / PO → sign-off → versioned release.
  • Default cloud is AWS (region me-central-1); Azure and on-prem are offered on request.
  • Deployment infrastructure is provided by Siraj Finance; capacity is sized from Siraj Finance’s volume data.

Lead capture & onboarding

  • Leads arrive from multiple sources; the RM / sales officer performs initial qualification.
  • Deduplication is provided by the core-banking or AML system and consumed via API — not built inside the CRM.
  • Two customer types (Individual, Corporate) with separate checklists and KYC/AML programmes; one checklist per product; all configurable by the System Administrator.
  • Corporate onboarding covers UBO / director / signatory / guarantor identification.
  • Siraj Finance supplies all document checklists, email templates and the Sharia-compliant FOL templates.

Customer portal

  • A unique, secure link per customer; Case ID + password generated on case creation and emailed; access restricted to that one customer.
  • The portal shows the full case timeline from day one; Phase 1 delivers the web portal + secure messaging.

AI document intelligence & OCR

  • PaddleOCR with Unique IT Solution’s own models / logic; no external OCR API.
  • Phase 1 targets English documents; Arabic / mixed / scanned / handwritten to be validated by experiment.
  • Siraj Finance defines the fields to extract, validation rules and the expected AI summary per document type.

AML / KYC / screening

  • Screening is performed by Siraj Finance’s existing compliant system; the CRM only sends data and stores results (“postman”), so the CRM needs no separate regulatory certification.
  • Screening providers are subscription-based with APIs (LSEG World-Check One, Sumsub, LexisNexis, …); the CRM is integration-ready for 3–4 configurable providers.
  • FIU / regulatory reporting and the policy engine (data localisation, etc.) stay in Siraj Finance’s systems.
  • AI findings are reconciled against the screening system’s findings (“AI limits”).

Risk, credit, CAD & FOL

  • Siraj Finance provides the risk-rating algorithm and the Low / Medium / High parameters.
  • Overrides require a mandatory reason / justification.
  • The credit officer decides manually; AI is decision-support only; CAD verifies every stage before FOL generation.
  • Pre-built, configurable conditions support “approve with condition”.
  • FOL lifecycle: draft → legal review → issue from the communication hub → acceptance → CAD document perfection → version-controlled, locked, non-editable final PDF.
  • Generic Sharia benchmarks are adequate for v1; Siraj Finance guides on the specifics.

Trade finance, lending operations & LOS

  • Siraj Finance runs its own core banking / LOS for trade finance and lending.
  • Unique IT Solution’s scope ends at onboarding + CAD verification + offer acceptance; Siraj’s team then punches the case into the LOS.
  • The CRM retains disbursement-milestone data (amount, conditional approval); disbursement executes in the LOS.

Communication hub & Microsoft 365

  • Microsoft 365 Graph API captures inbound and tracks outbound email; every RM–customer email is tied to the customer timeline.
  • Phase 1 = email channel only; SMS & WhatsApp are Phase 2.

Repository, incentives, reporting & configuration

  • A centralised, searchable document repository holds accepted letters, FOL snapshots and audit trails.
  • Incentives are system-calculated from transparent rules + milestone evidence + management approval; the current model is a placeholder pending the full structure and hierarchy rules from Siraj Finance.
  • Role-based dashboards per function (Head of Business, Sales, Credit, CAD, Compliance).
  • The System Administrator configures branch / sales hierarchy, RBAC, checklists, templates, conditions and workflow; template / workflow / permission changes need formal approval + version control.
  • English + Arabic throughout.

Integrations

  • Siraj Finance holds the required subscriptions for AECB (Al Etihad Credit Bureau), Emirates ID and other government APIs.
  • Integrations are built to each provider’s published API spec and certification.
  • Connectors are configurable multi-provider (URL / port / ID / password).

Non-functional

  • 2FA, SSO readiness, password policy, session timeout, device / IP monitoring.
  • PII / sensitive-field masking per regulator; access only to privileged roles.
  • Production + backups + disaster recovery.
  • Hosting is subject to Siraj Finance security-team approval.
  • Not currently certified for NIST AI RMF; open to pursuing certification.
